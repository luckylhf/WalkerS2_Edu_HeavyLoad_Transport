# HTTP 运动代理安装与启动指南

本项目已将 Walker S2 HTTP 运动代理完整放在
[`tools/motion_http_proxy/`](../tools/motion_http_proxy/README.md)，不再依赖工作区外的
代理目录。代理把本项目的 HTTP 请求转换为 `motion` 容器内的 ROSA service CLI 调用：

```text
navigate_box_workflow.py / trigger_detect_box.py
  ├─ GET  /healthz
  ├─ POST /v1/call_action   （例如 s2/move_biped_home）
  └─ POST /v1/motions       （双臂和 biped 关节目标）
             ↓
motion_http_proxy → rosa → manipulation_task_manager
```

> 代理不提供碰撞规划、力控、动作撤回或急停。代理启动成功、HTTP 200 均不代表机器人
> 已安全到位。首次部署必须使用现场验证过的停止手段和本项目 debug 流程。

## 2. 安装到机器人

目录内的二进制已经预编译好，不需要在设备上重新编译。在开发机当前项目根目录，将
内置目录同步到 Walker 宿主机约定目录：

```bash
cd ~/work/s2_demo3
rsync -av tools/motion_http_proxy/ \
  <walker-ssh>:/debug/proxy_server/
```

登录设备确认二进制可执行：

```bash
cd /proxy_server
chmod +x run_motion_http_proxy.sh call_action.sh call_motion.sh motion_http_proxy
test -x ./motion_http_proxy
```

所需环境：`/opt/walker/setup.bash` 以及加载后可用的 `rosa`。不需要 Python、pip
或 CMake。

## 3. 启动方式

### 3.1 前台启动

在 `motion` 容器中：

```bash
cd /proxy_server
export HTTP_PROXY_HOST=0.0.0.0
export HTTP_PROXY_PORT=12300
export MOTION_PROXY_API_KEY='替换为现场密钥'
export MOTION_PROXY_LOG_COMMAND=0
exec ./run_motion_http_proxy.sh
```

入口会加载 `/opt/walker/setup.bash`，检查代理二进制和 `rosa`，然后监听端口。按
`Ctrl+C` 只停止代理进程，不会撤回已经提交给机器人的动作。

### 3.2 UDoKe `motion` 模块

宿主机 `/debug/proxy_server` 挂载到容器 `/proxy_server`，模块配置示例：

```yaml
proxy_server:
  extends: mc_common
  command: "/proxy_server/run_motion_http_proxy.sh"
  ports:
    - "12300:12300"
  volumes:
    - /debug/proxy_server:/proxy_server
  environment:
    HTTP_PROXY_HOST: "0.0.0.0"
    HTTP_PROXY_PORT: "12300"
    MOTION_PROXY_API_KEY: "替换为现场密钥"
    MOTION_PROXY_LOG_COMMAND: "0"
```

使用 UDoKe 控制模块启动、停止和重启。查看容器日志：

```bash
docker logs -f walker-motion.proxy_server-1
```

当前内置目录不含 systemd unit、Dockerfile 或 Compose 文件；是否开机自启取决于现场
UDoKe 模块配置，不能仅凭本项目文件断言已启用。

## 4. 配置

| 变量 | 用在哪一端 | 说明 |
| --- | --- | --- |
| `HTTP_PROXY_HOST` | 服务端 | 监听 IPv4；容器默认 `0.0.0.0` |
| `HTTP_PROXY_PORT` | 服务端 | 默认 `12300` |
| `WALKER_SETUP` | 服务端 | 默认 `/opt/walker/setup.bash` |
| `PROXY_BIN` | 服务端 | 代理二进制路径 |
| `ROSA_BIN` | 服务端 | 默认 `rosa` |
| `MOTION_PROXY_API_KEY` | 两端 | 非空时三个接口都要求 `X-API-Key` |
| `MOTION_PROXY_LOG_COMMAND` | 服务端 | `1/true` 记录完整参数，仅临时调试 |
| `MOTION_BASE_URL` | 本项目 | 默认 `http://192.168.11.2:12300` |
| `BASE_URL` | helper | `call_*.sh` 使用，默认同上 |

密钥只能通过受控环境变量注入，禁止写进源码、配置仓库或日志。HTTP 本身没有 TLS；端口
应只暴露在受控网络，或绑定回环后经 SSH 隧道访问。

## 5. 验证

先只检查健康接口，不触发运动：

```bash
export MOTION_BASE_URL=http://192.168.11.2:12300
export MOTION_PROXY_API_KEY='替换为现场密钥'

curl_args=(-fsS)
if [[ -n "${MOTION_PROXY_API_KEY:-}" ]]; then
  curl_args+=(-H "X-API-Key: ${MOTION_PROXY_API_KEY}")
fi
curl "${curl_args[@]}" "${MOTION_BASE_URL}/healthz"
```

成功应返回 `{"status":"ok"}`，仅证明 HTTP 进程可达。

动作 helper 默认不发送任何请求。真机会运动，只有完成开机前置、清空运动区并确认急停后
才能显式执行：

```bash
cd ~/work/s2_demo3/tools/motion_http_proxy

# 真实调用 move_biped_home
./call_action.sh --execute

# 真实发送已审核的关节目标；禁止直接使用占位示例
./call_motion.sh --execute /path/to/reviewed-motion.json
```

`/v1/motions` 没有 dry-run，因此不提供“安全试运动”命令。HTTP 200 后仍必须通过
`/mc/joint_states`、TF 和机器人告警独立判断到位。

## 6. 本项目运行前配置

运行导航抓放程序的同一终端：

```bash
export MOTION_BASE_URL=http://192.168.11.2:12300
export MOTION_PROXY_API_KEY='替换为现场密钥'
```

本项目会让 `/healthz`、`/v1/call_action`、`/v1/motions` 都携带相同 key。未启用服务端
鉴权时不要设置 key。

## 7. 常见错误

| 状态/现象 | 原因与处理 |
| --- | --- |
| 401 | 两端 key 缺失或不一致 |
| 409 | 已有动作执行中；禁止盲目重发 |
| 415 | POST 缺少 `Content-Type: application/json` |
| 502 | ROSA CLI 失败；检查响应 output 和容器日志 |
| `missing Walker environment` | 不在正确容器或 `WALKER_SETUP` 错误 |
| `rosa was not found` | Walker 环境未正确加载 |
| `Address already in use` | 已有代理占用端口，先确认进程/模块状态 |
| curl 超时 | 检查设备网络、端口映射和模块状态 |
| HTTP 200 但未到位 | 检查 joint_states、TF 和机器人告警，不要重复发送 |

完整字段、状态码与安全说明见本项目内
[代理 README](../tools/motion_http_proxy/README.md)。
